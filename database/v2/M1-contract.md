# M1 database contract

This note records the physical contract sent to the coordinator for review and the implementation constraints for the v2 migration.

Implementation status: the migration is `supabase/migrations/20260906093036_m1_private_foundation.sql`, matching the applied remote migration history. The migration and local M1 fixtures passed on fresh PG17 rebuilds; target advisors report no warnings/errors beyond intentional deny-all/private-scope INFO entries.

- Schemas: private `app`, `catalog`, `reco`, `ops`, and `migration`; browser roles have no access. `vault_app` and `vault_worker` are `NOLOGIN`, `NOSUPERUSER`, `NOBYPASSRLS` group roles. Default privileges are revoked explicitly.
- Accounts: `app.accounts` uses an internal integer key plus preserved unique UUID. `account_kind` is `manual | steam`; guests are ephemeral. Verified Steam identity lives in `app.steam_profiles` and is unique only when `verified`; duplicate unverified public profiles remain valid. Capabilities are tri-state and preferences are bounded JSON.
- Sessions: `app.sessions` contains a unique 32-byte HMAC digest, session kind, expiry/revocation, and account FK. A narrowly scoped definer resolver accepts the digest plus expected `manual`/`verified_steam` kind, uses the database clock internally, and returns only the minimal principal (session/account IDs, public UUID, account/session kinds, verified flag, expiry); profile display fields are a tenant followup. Raw tokens/secrets are never stored or returned.
- User facts at M1: active library is `(account_id, game_id, playtime_minutes)` and sparse state originally carried Sleep timestamps. The locally prepared 12 September Blacklist follow-up supersedes that product shape with an undated `blacklisted` boolean while leaving timed `app.snoozes.until_at` separate. Activity and retired rows retain observation timestamps; daily minutes use `bigint`. Family and collection relationships include compound tenant FKs. Family member count is serialized on the parent account row and candidate JSON is bounded.
- Authorization: every tenant table has forced RLS with both `USING` and `WITH CHECK` against fail-closed transaction-local `app.account_id`. Direct runtime writes to identity, verification, session digest, and import-owned library fields are unavailable. Worker grants are narrow and never include sessions or blanket private access. The target project marker is readable through marker-only access for the least-privileged runtime.
- Promotion primitives: `ops.auth_intents` binds a digest/nonce to the exact `(account_id, session_id)` and expiry/consumption; `ops.account_merges` records minimal audit and source alias/tombstone state. Full promotion/merge execution remains later milestone work.
- Tests: clean replay, malformed/missing/overflow/negative context, principal/session kind/expiry/revocation, duplicate verified/unverified identity, cross-account reads/writes/FKs, pooled connection reuse/rollback, family cap/lock, sparse-retention semantics, marker/exposure, and default ACLs. Portable rebuild guidance documents CLI migration creation, clean PG17 replay, role bootstrap and marker verification.

The coordinator approved this contract with the corrections recorded here. The coordinator must review the final migration and local fixtures before any target apply.
